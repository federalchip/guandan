# GitHub 开源展示预计划

日期：2026-10-21
状态：仓库展示材料准备中；公开在线试玩未上线

## 目标与边界

让访问 GitHub 仓库的人快速看懂、验证并在本地运行当前的单人掼蛋 v1 MVP。展示应准确区分“本地可玩”和“公开在线试玩”；后者仍需按[小规模公开上线计划](online-solo-launch-plan.md)完成资源保护、目标环境验收、部署与运维。

GitHub Pages 只能托管静态前端。当前前端请求同源根路径 `/api/v1`，牌局由 Spring Boot 后端和单 JVM 内存维护，因此不能把 `frontend/dist` 单独部署到 Pages 后称为在线试玩。

## 3. v1 Release 准入与发布

- [ ] 审查更新后的 README 与展示材料，确认哪些内容属于 v1；不要把当前未实施的公开上线计划写成已完成。
- [ ] 在准备发布的提交上运行后端测试、前端单测、类型检查和生产构建；记录命令、结果与提交 SHA。按需引用已有 T10/T11 报告，不能以旧报告代替新提交验证。
- [ ] 确认需要发布的提交已合并到 `main` 并成功推送，工作区无遗漏的发布文件。
- [ ] 创建 GitHub Release，标签建议 `v1.0.0`（仅在没有同名标签时）；标题建议 `掼蛋 v1：本地单人 MVP`。正文说明已实现功能、JDK/Node 要求、启动步骤、测试依据与当前限制。
- [ ] 发布后从未登录 GitHub 的浏览器访问仓库和 Release，检查 README、许可证、图片和链接。若仓库不公开，则按实际可见性验收，不声称公众可访问。

Release 的创建与仓库公开会使内容对外可见；在执行前需完成对应文件、标签和可见性的人工复核。此预计划本身不是 Release，也不意味着公网游戏服务已经部署。

## 4. 可选的 GitHub Pages 展示页

若以后想在仓库之外提供一页可点击的项目介绍，可以用 GitHub Actions 构建静态介绍页并发布到 Pages。页面可放截图、功能、仓库链接和本地运行说明。它不应直接承载当前需要 `/api/v1` 的游戏前端；如果要提供真实在线试玩链接，应先按[公开上线计划](online-solo-launch-plan.md)部署并验收独立后端及同源 HTTPS 入口，再从介绍页链接过去。
