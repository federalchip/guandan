# T11 浏览器验收与交付计划

依据主计划 T11（`2026-10-06-guandan-v1-mvp.md` 第 491–503 行）执行。现有工作区含 v1 牌桌体验改动，保留并在最终验收中一起覆盖。

## 设计与边界

- Playwright 在独立端口启动真实 Spring HTTP 服务与 Vite 页面，经同源 `/api` 代理通信。
- 固定短手牌、可多声明手牌只在 `backend/src/test/java` 的 `e2e` profile 中注入内存存储；不增加生产调牌接口。测试用例通过浏览器会话恢复这些已知测试局。
- 浏览器测试以 API 快照、请求次数、持久化 pending、DOM 可观察状态为断言；事件播放用条件等待，不按固定时长猜结果。
- 保留工作区现有未提交改动。T11 交付前复验包括 Playwright、后端标准测试、前端单测、类型检查和构建。

## 任务

1. 接入 Playwright 测试依赖、独立端口配置与服务启动；增加测试专用固定局注入。先让基础浏览器用例因缺失能力而失败，再完成最小配置。
2. 覆盖真实整局主线：开始、27 张、提示、选牌、出牌、机器人事件、回到真人；短手牌结算与新 game_id。
3. 覆盖恢复和隔离：双击、声明选择、刷新、响应丢失后原请求重试、旧局失效、新局不受旧回调影响。
4. 覆盖事件播放：播放中禁止出牌、公开牌逐座出现、权威快照取消过期播放；仅修复测试揭示的产品问题。
5. 完整验证、人工浏览器试玩、更新 README 和 `docs/test-report-v1.md`，列出运行环境、命令结果与已知限制。全部通过后提交 T11 交付变更，并更新阶段状态。

## 重点审查

- 测试 fixture 不应被打进生产 JAR，也不能通过生产 HTTP 路由改牌。
- 断网/刷新重试必须沿用 request_id，重复请求不得重复扣牌或重播。
- 新局创建后旧局响应和 pending 不得污染当前牌局。
- 测试不能只证明页面文案出现，还要与真实后端状态一致。
